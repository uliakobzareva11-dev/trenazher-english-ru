# Тренажёр английского — правила работы

Сайт: https://trenazher-english.ru · весь тренажёр — один файл `index.html` (~950 КБ, 18 тем, ~950 заданий).
Эти правила нужны, чтобы при доработке ничего не слетало и сайт всегда совпадал с рабочим файлом.

## Где что лежит
| Что | Где | Зачем |
|---|---|---|
| рабочий файл | `index.html` в этой папке | правим только его |
| история | GitHub, ЗАКРЫТЫЙ репозиторий `trenazher-english-ru` | каждый коммит — точка возврата и копия вне компьютера |
| список учеников | `../trenazher-dostup/ucheniki.json` — ВНЕ git | имена, коды, сроки, оплаты: данные детей в git не кладём |
| сборка | `../trenazher-dostup/sait/` | зашифрованный index.html: без кода из ссылки не открывается |
| сайт | trenazher-english.ru ← ОТКРЫТЫЙ репозиторий `trenazher-english-site` | в нём только сборка, один коммит |

Сайт показывает не рабочий файл, а его закрытую сборку. Правка в `index.html` попадёт к ученикам только после `vylozhit`.

⛔ Не править файл через сайт GitHub и не держать вторую копию «где-то ещё»: копии разъедутся, и правка потеряется.
Если на GitHub что-то меняли вручную — сначала `git pull`, потом работа.

## Перед правкой
1. `git status` — чисто. Есть несохранённое — сначала коммит «точка возврата».
2. ⛔ Файл большой, его **никогда не переписываем целиком**. Только точечные правки в нужном месте.
   Переписанный целиком файл — главная причина «всё слетело»: теряются куски, которых в этот момент не видно.
3. Новая тема = запись в `SETS` + её id в `MENU`. Чужие темы не трогаем.

## Коммиты: когда и что в них кладём
Коммит — сохранённая точка в истории, к ней можно вернуться в любой момент. `push` отправляет её на GitHub:
без него точка живёт только на маке, и копии вне мака нет.

**Когда:**
- перед каждой правкой — точка возврата;
- после каждой законченной порции: одна тема, одна пачка заданий, одна починка. Одно изменение — один коммит,
  правки за неделю в один коммит не копим;
- сразу после коммита — `git push`.

**Подпись коммита** — что сделано, по-русски и конкретно: «Тема Present Continuous: 40 заданий»,
«Исправлен ответ в задании про has gone». Не «правки», не «update».

**Кладём:** `index.html`, `CNAME`, `.nojekyll`, `check.py`, `.githooks/`, `.gitignore`, `.claude/rules/` —
то, из чего собирается сайт, и правила работы.

**Не кладём.** В git — только то, из чего собирается сайт. Git хранит каждую версию файла навсегда: тяжёлый файл,
заменённый десять раз, весит в истории вдесятеро больше, и удалить его потом из истории трудно. У GitHub пределы:
файл больше 100 МБ не примет, репозиторий и сайт — до 1 ГБ. Исходные материалы держим в отдельной папке рядом, не в репозитории:
- отчёты учеников, имена, телефоны, оценки — это данные детей;
- сканы и PDF учебника Spotlight, раздатки, таблицы — чужие материалы, и тяжёлые;
- пароли, ключи, токены;
- копии рабочего файла (`index copy.html`, `index-old.html`) — история уже в git, копии путают, какая версия настоящая;
- служебный мусор мака (`.DS_Store`);
- файлы больше 5 МБ.

Большую часть этого не пускает `.gitignore`, а замок останавливает коммит, если такой файл всё-таки добавлен.
Перед коммитом смотреть `git status`: в списке должно быть только то, что меняла.

## Перед публикацией
1. `python3 check.py` → должно быть ✅. Стоп — не публикуем, разбираемся.
2. Открыть `index.html` в браузере: пройти новую тему, нажать озвучку, сузить окно до ширины телефона.
3. Показать Юле, что изменилось (темы, сколько заданий добавлено) → её «ок».
4. `git add index.html && git commit -m "что сделано" && git push`

## После публикации
- Через пару минут: `python3 check.py --live` → «на сайте ровно твой файл».
- Не совпало — GitHub обновляет до 10 минут, подождать и повторить. Через 15 минут то же — push не прошёл.
- «Готово» говорить только после ✅ от `--live`.

## Если сломалось
- Откат: `git log --oneline` → `git checkout <номер> -- index.html` → `python3 check.py` → коммит «откат к …» → push.
- ⛔ `git push --force`, `git reset --hard`, удаление истории — только с Юлей.

## Платный доступ: личные ссылки
У каждого ученика своя ссылка `trenazher-english.ru/#код`, общего пароля нет. У кода есть срок — поле «до» в списке.
Сайт сам сроки не проверяет: истёкший ученик открывает тренажёр, пока сайт не пересобран. Поэтому:

**В начале каждой работы** — `node zamok/dostup.mjs srok` (запускается сам при старте сессии в этой папке) и показать Юле:
у кого срок кончился, у кого кончается за 3 дня. Кончился и ещё открывает → напомнить пересобрать и выложить.

| Ситуация | Команда |
|---|---|
| новый ученик оплатил | `node zamok/dostup.mjs dobavit "Имя" ГГГГ-ММ-ДД 400` → ссылку Юле, строку чека Юле |
| свой, бесплатно | `node zamok/dostup.mjs dobavit "Имя" ГГГГ-ММ-ДД` — без суммы, срок длинный |
| продлил | `node zamok/dostup.mjs prodlit "Имя" ГГГГ-ММ-ДД 400` — ссылка прежняя |
| «оплачу завтра» | `prodlit` на день, только если Юля так решила |
| срок кончился / правка в тренажёре | `node zamok/dostup.mjs vylozhit` → через пару минут `python3 check.py --live` |

- ⛔ Авансом срок не продлеваем — только после оплаты. Не продлил — доступ закрывается, не упрашиваем.
- Оплата сейчас — переводом Юле. Чек в «Мой налог» пробивает Юля при каждой оплате (строку печатает `dobavit`/`prodlit`).
- Перед `vylozhit` с изменениями тренажёра — сначала обычный порядок: `check.py` → «ок» Юли → коммит в рабочий репо.
- `vylozhit` перезаписывает историю сайтового репо (`git push --force`) — там только сборка, так задумано.
  В рабочем репозитории `trenazher-english-ru` force по-прежнему запрещён.
- Делая что-то для Юли, спрашивать, удобно ли ей, и предлагать варианты; решение — её.

## Прогресс учеников
Хранится в браузере ученика под ключами `STORE_KEY` и `PROGRESS_KEY` и привязан к адресу сайта.
- ⛔ Не менять имена ключей и адрес сайта — у всех учеников обнулится прогресс.
- Нужно поменять формат хранения — читать старый ключ и переносить данные, как уже сделано с `trenazher-english-progress-v1`.

## Правда в заданиях
Ученик верит тренажёру. Неверный ключ ответа хуже, чем отсутствие задания.
- У каждого задания: верный ответ `a`, неверные `wrong`, объяснение `why`, источник `src` (учебник и страница, кодификатор ФИПИ).
- Правило грамматики и чтения пишем из учебника или кодификатора, а не из памяти модели. Не уверен — спросить Юлю, а не писать правдоподобное.
- Новое задание проверить вторым проходом: решить заново, не глядя в ключ. Не совпало — разобраться до публикации.
- В отчётах учеников одно задание валят многие — сначала проверить само задание (ключ, формулировку), потом ученика.
- `check.py` сам ловит противоречия: верный ответ среди неверных, пропусков `___` не столько, сколько ответов, вопрос повторяется, нет объяснения.

## Включить замок (один раз)
`git config core.hooksPath .githooks` — после этого коммит не пройдёт, пока `check.py` говорит «стоп».
Убрала тему намеренно: `python3 check.py --force "что и зачем"`, затем `git commit --no-verify`.

## Отчёт Юле после каждой работы
Что изменилось · вывод `check.py` · вывод `check.py --live`. Без этих трёх строк работа не закончена.

## Не делать
- не переписывать файл целиком
- не публиковать без ✅ `check.py`
- не менять ключи прогресса и адрес сайта
- не класть в файл пароли, ключи и данные учеников
